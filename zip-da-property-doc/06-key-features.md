# 주요 기능

> Property 서비스가 소유한 매물 탐색·등록·인증·파일·찜·신고 처리이다. 현재 구현 범위와 다른 저장소 연동이 필요한 V3 예정 범위를 구분한다.

## 1. 지도 기반 매물 검색

현재 지도 영역과 확대 수준에 따라 지역 집계 또는 개별 매물을 반환한다.

- 확대 수준 `13~14` → 시·도 집계
- 확대 수준 `11~12` → 시·군·구 집계
- 확대 수준 `8~10` → 읍·면·동 집계
- 확대 수준 `5~7` → 클러스터링용 매물 좌표
- 확대 수준 `1~4` → 개별 가격 마커
- 매물·거래 유형, 가격, 관리비, 면적, 방 개수, 등록 주체와 편의 조건 필터
- 최신순·가격순·면적순 정렬
- 개별 매물 최대 500건 반환과 초과 여부 `truncated` 제공

검색 대상은 공개·인증 상태이며 거래 가능한 매물로 제한한다. MySQL 공간 함수로 현재 지도 영역에 포함되는 공개 좌표만 조회한다.

> **구현 효과**  
> 넓은 지도에서는 지역별 집계로 응답량을 줄이고, 확대 시 실제 탐색에 필요한 매물 위치와 가격으로 전환하는 검색 구조이다.

## 2. 매물 등록과 수정

매물 등록 시 요청자 역할과 등록 주체, Member 쓰기 권한, 가격 조합, 지역, 주소·좌표, 단지, 옵션과 이미지를 검증한다.

```text
등록 요청
  → 역할·Member 쓰기 권한 확인
  → 가격·지역·주소·단지 검증
  → 등록 전 위험 평가
  → 매물·주소·이미지·옵션 저장
  → Revision·상태 이력·감사 이력 기록
  → 공개 검수 대기 상태 생성
```

- 일반 회원 → 집주인 또는 세입자 직접 등록
- 중개사 → 중개 매물 등록
- 최초 공개 상태 → `IN_REVIEW`
- 최초 거래 상태 → `AVAILABLE`
- 최초 인증 상태 → `UNVERIFIED`
- 수정 시 실제 변경 필드만 Revision에 기록
- 주소 변경 시 지역 검증과 공개 위치 재생성
- 이미지 제거 시 DB 반영 후 MinIO 객체 삭제

### 2.1. 중복 등록과 동시 수정 제어

- 등록 요청에 `Idempotency-Key` 사용
- 요청 본문을 SHA-256으로 비교
- 같은 키·같은 요청 → 최초 등록 응답 재사용
- 같은 키·다른 요청 → 충돌 처리
- 처리 중인 같은 요청 → 중복 실행 차단
- 멱등 기록 → 24시간 유지 후 예약 작업으로 정리

수정·상태 변경·삭제·복구·인증 요청에는 `If-Match`와 본문의 매물 버전을 함께 전달한다.

```text
If-Match: "7"
요청 본문 version: 7
현재 DB version: 7
  → 처리 성공, version 증가

현재 DB version: 8
  → VERSION_CONFLICT, 기존 데이터 유지
```

JPA 낙관적 잠금과 버전 검증으로 다른 요청이 먼저 변경한 매물을 덮어쓰지 않도록 제어한다.

### 2.2. 매물 등록 전 위험 평가

매물 등록 전에 중복·허위·비정상 등록 가능성을 점수화해, 위험한 매물은 등록을 차단하고 검토가 필요한 매물은 우선 관리 대상으로 분류한다.

- 동일 주소·가격·등록자
- 동일 이미지 SHA-256
- 동일 주소와 동일 이미지 조합
- 비정상 가격 범위
- 금칙어
- 전화번호·외부 메신저·URL을 통한 외부 연락 유도

신고 접수 후 처리하는 기능이 아니라, 문제 가능성이 있는 매물이 등록되기 전에 차단하거나 검토 대상으로 구분하는 예방 처리이다.

| 점수 | 판정 | 처리 |
| --- | --- | --- |
| `0~69` | `PASS` | 등록 진행 |
| `70~89` | `IN_REVIEW` | 등록 후 검수 우선순위에 활용 |
| `90~100` | `BLOCKED` | 등록 차단 |

차단된 등록도 평가 이력은 별도 트랜잭션으로 보존한다.

## 3. 매물 위치 검증과 비식별 공개

매물 등록·주소 수정 시 정확 위치를 검증하고 공개 위치를 생성한다. 지도 검색과 매물 조회에서는 생성된 공개 위치만 사용한다.

### 3.1. 매물 위치 검증

- 매물 등록 전: 법정동 코드와 좌표가 같은 Region 경계에 포함되는지 확인해 잘못된 주소·좌표 조합을 막는다.
- 매물 등록: 검증한 정확 위치를 기준으로 공개 주소와 공개 좌표를 생성해 저장한다.
- 주소·좌표 수정: Region 경계를 다시 확인하고 공개 위치를 새로 생성한다.

### 3.2. 공개 위치 생성

```text
검증된 정확 주소·좌표
  → HMAC-SHA256 기반 방향·이동 거리 계산
  → 정확 위치에서 80~180m 이동
  → 지역 경계를 벗어나면 경계 안쪽으로 보정
  → 공개 주소·공개 좌표 생성
```

### 3.3. 공개 위치 적용

- 정확 주소와 좌표: 등록·수정·내부 검증에 사용
- 공개 주소와 좌표: 지도 검색, 지도 마커, 매물 목록·상세에 사용
- 지도 검색: `public_location`만 조회
- 동일 매물·주소: 일관된 공개 위치 유지
- 위치 좌표: WGS84 `SRID 4326` 기준
- 공개 위치 생성 비밀키: 32바이트 이상 설정
- 정확 위치는 공개 응답과 지도 검색에 사용하지 않고, Region 경계 안의 근사 공개 위치만 제공해 위치 노출 범위를 제한

## 4. MinIO 파일 처리

사용자는 업로드 권한이 포함된 제한 시간 URL로 MinIO에 파일을 직접 올리고, Property 서비스는 업로드 완료 파일의 실제 형식과 무결성을 확인한 뒤 업무 파일로 사용한다.

```text
업로드 준비
  → 파일 정보 등록
     · 용도: 매물 이미지 / 인증 증빙 / 신고 증빙
     · 최대 30개, 파일 1개 최대 20MB
  → 15분 유효 업로드 URL 발급
     · 업로드 URL: 제한 시간 동안 MinIO에 파일을 올리는 주소

MinIO 직접 업로드
  → 업로드 완료 확인 요청
     · 파일을 올린 사용자만 완료·연결·삭제 가능
  → 파일 크기·허용 형식·실제 파일 내용·SHA-256 검증
     · 허용 형식: JPEG / PNG / GIF / WebP
  → VERIFIED 처리
  → 매물 이미지·인증 증빙·신고 증빙으로 연결

열람
  → 공개 이미지·관리자 증빙 열람 URL 발급
     · 열람 URL: 15분 동안 파일을 보는 주소

파일 정리와 삭제 재시도
  ├─ 미연결 매물 이미지 정리
  │   → VERIFIED 후 24시간 이상 매물 이미지에 연결되지 않은 파일 조회
  │   → DB 파일 정보 논리 삭제 커밋 후 MinIO 객체 삭제 요청
  │
  └─ 삭제 실패 객체 재시도
      → DB에서는 삭제됐지만 MinIO 객체가 남은 파일 조회
      → 다음 예약 작업에서 MinIO 객체 삭제 재요청
```

매물 인증 증빙의 보관 기간과 정리 대상 판단은 [매물 인증과 공개 검수](#5-매물-인증과-공개-검수)에서 처리한다. 이 항목은 파일의 MinIO 삭제와 실패 재시도 방식을 다룬다.

## 5. 매물 인증과 공개 검수

매물의 등록 주체·증빙 유효성을 확인하고, 별도의 공개 검수로 사용자 검색 노출 여부를 결정한다.

### 5.1. 인증 증빙 심사

- 매물 작성자가 집주인·세입자·중개사 유형의 증빙 파일로 인증 신청
- 매물 작성자만 신청 가능하며 파일 소유자·검증 완료 상태·증빙 용도 확인
- 같은 유형의 검토 대기(`IN_REVIEW`) 인증 신청 중복 차단
- 관리자(`CS_ADMIN`, `SUPER_ADMIN`)가 인증 요청 승인 또는 반려
- 승인 시 매물 인증 상태를 `OWNER_VERIFIED`, `TENANT_VERIFIED`, `AGENT_VERIFIED` 중 해당 상태로 변경하고 30일간 유효 처리

### 5.2. 공개 검수

- 매물 생성 시 공개 상태는 `IN_REVIEW`
- 관리자가 매물 내용과 현재 인증 상태를 검토해 `PUBLISHED` 또는 `REJECTED` 처리
- 인증 승인만으로 매물이 자동 공개되지는 않음
- 반려된 매물은 작성자가 보완 후 다시 검토 요청 가능

### 5.3. 실제 검색 노출 조건

공개 검색·목록·지도에 노출하려면 다음 조건을 모두 충족해야 한다.

- 공개 상태: `PUBLISHED`
- 거래 상태: `AVAILABLE` 또는 `RESERVED`
- 인증 상태: `OWNER_VERIFIED`, `TENANT_VERIFIED`, `AGENT_VERIFIED` 중 하나
- 매물과 주소가 삭제되지 않은 상태

인증 증빙 심사는 등록 주체의 신뢰를 확인하는 절차이고, 공개 검수는 사용자에게 매물을 노출할지 결정하는 절차이다.

### 5.4. 인증 유효기간과 재인증

- 만료 7일 전부터 재인증 신청 가능
- 재인증 심사·반려 중 기존 인증은 원래 만료일까지 유지
- 재인증 승인 시 새 인증은 30일간 유효하며 기존 인증은 `EXPIRED`로 대체 처리
- 인증 만료 시 매물 인증 상태를 `EXPIRED`로 변경하고 공개 검색 대상에서 제외

### 5.5. 예약 작업

예약 작업은 인증 상태와 증빙 보관 상태를 시간 기준으로 유지한다.

- 인증 만료 · 60초 간격 → 유효기간이 지난 인증과 매물 인증 상태를 `EXPIRED`로 변경하고 Revision·상태 이력·감사 이력·만료 이벤트 기록
- 재인증 대상 · 15분 간격 → 만료 7일 이내 인증의 `renewalNotifiedAt` 기록, 감사 이력과 Kafka 이벤트 발행
- 인증 증빙 정리 · 15분 간격 → 인증 종료 후 30일이 지난 증빙 연결·파일 정리
- 다른 활성 인증이 참조하는 파일 → 정리 대상에서 제외

현재 소스에는 이메일·푸시 직접 발송이 없으므로, 재인증 대상 처리는 안내 발송이 아니라 기록과 이벤트 발행으로 표현한다.

인증이 만료된 매물은 공개 검색 조건에서 제외된다.

## 6. 관심 매물

로그인한 일반 회원과 중개사가 공개 가능한 매물을 찜하거나 해제할 수 있다.

- `PUT` 요청으로 찜 상태를 명시해 반복 요청 결과의 일관성 유지
- 회원·매물 조합의 활성 찜 중복 방지
- 비공개·거래 완료·미인증 매물의 신규 찜 차단
- 내 찜 목록을 `cursor`와 `size`로 분할 조회
- 대표 이미지는 제한 시간 Presigned URL로 제공
- 현재 공개 조건을 충족하지 않는 매물은 찜 목록에서 제외
